Under the Hood

A 9-Phase AI Pipeline That
Preserves Document Context

Rather than sending your document as a raw text dump, WalnutAI section-aware chunks it, vectorizes it, and uses RAG to pull the most relevant sections as context for each extraction call.

Pipeline Execution — per document
1
Ingestion
Document Ingestion & Parsing
Raw document received — PDF, DOCX, Confluence page, or plain text. Parser extracts raw content while preserving layout metadata.
PDFDOCXConfluencePlain text
2
Analysis
Structure & Hierarchy Detection
Headings, sub-sections, numbered lists, and tables are detected. A document outline tree is built so the AI understands the hierarchy.
Heading treeSection mapDepth levels
3
Chunking
Section-Aware Semantic Chunking
Splits at semantic boundaries — not arbitrary character limits. Each chunk carries its parent section header and hierarchy path as metadata, keeping context intact.
Semantic splitParent headerHierarchy path
4
Embedding
Vectorization with Context Metadata
Each chunk is embedded via a high-dimensional embedding model. Section title, page number, and structural depth are stored alongside the vector.
1536-dim vectorsRich metadata
5
Indexing
Vector Store Indexing
Vectors indexed with HNSW for sub-millisecond approximate nearest-neighbor search. Supports multi-tenant isolation per project.
HNSW indexPer-project isolation
6
Retrieval
Per-Extraction RAG Query
For each user story or requirement to extract, a targeted query is formulated. The vector store returns the top-k most semantically relevant chunks.
Semantic searchTop-k retrievalScore threshold
7
Assembly
Context Window Assembly
Retrieved chunks re-ordered by document position and stitched with their section headers — reconstructing a coherent, structure-preserving context block for the LLM.
Re-rankedPosition-sortedHeader-stitched
8
Extraction
Grounded AI Story Generation
LLM receives the assembled context and generates user stories, acceptance criteria, and edge cases — grounded in the document's actual language and intent.
GPT-4oStructured outputSource citations
9
Output
Structured Delivery & Traceability
Each story is tagged with the source section it was derived from. Teams can trace every output back to the original document paragraph — full auditability.
Section tagsJira exportAudit trail
The Result
Stories reflect actual structure — not a flat summary of the whole document.
No hallucinated requirements — every output is grounded in retrieved source text.
Full traceability — each story cites the section it came from.
Long documents handled — context window never exceeded via RAG chunking.
WalnutAI vs. Raw Text Dump
❌ Without RAG

Entire doc crammed into one prompt. Structure lost. Stories are generic summaries.

✓ WalnutAI RAG

Only the relevant sections are retrieved. Stories match the document's actual intent.
